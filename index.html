1. Системи контролю версій та Git

Система контролю версій (СКВ, VCS — Version Control System) — це програмне забезпечення, яке зберігає історію змін файлів проєкту. Воно дозволяє повернутися до будь-якої попередньої версії, побачити, хто і коли вніс зміни, та організувати спільну роботу кількох розробників над одним кодом.

Типи систем контролю версій

ТипПринцип роботиПриклади
Локальні Історія версій зберігається лише на комп'ютері одного користувача. RCS
Централізовані Є один центральний сервер з історією; клієнти отримують з нього лише робочі копії. SVN (Subversion), CVS, Perforce
Розподілені Кожен учасник має повну копію репозиторію з усією історією змін. Git, Mercurial

Що таке Git

Git — розподілена система контролю версій з відкритим кодом. Її створив Лінус Торвальдс у 2005 році для розробки ядра Linux, після того як спільнота втратила можливість безкоштовно користуватися системою BitKeeper. Сьогодні Git — найпоширеніша СКВ у світі, на ній працюють сервіси GitHub, GitLab, Bitbucket.

На відміну від багатьох інших систем, Git зберігає не різницю між файлами, а знімки (snapshots) стану всього проєкту. Кожен знімок (коміт) ідентифікується унікальним хешем SHA-1, тому історію неможливо непомітно змінити.

Три стани файлів у Git

  • Modified (змінений) — файл змінено, але ще не підготовлено до коміту;
  • Staged (індексований) — зміни позначено для наступного коміту (git add);
  • Committed (зафіксований) — дані збережено в локальній базі репозиторію (git commit).

2. Основні можливості та переваги Git

РозподіленістьКожен розробник має повну копію репозиторію, тож робота можлива навіть без інтернету.
ШвидкістьБільшість операцій виконуються локально, тому працюють миттєво.
Гілки (branches)Легке створення та злиття гілок для паралельної розробки нових функцій.
Повна історія змінМожна побачити, хто, коли і що змінив, та повернутися до будь-якої версії.
Цілісність данихУсі об'єкти захищені контрольними сумами SHA-1 — пошкодження чи підміну буде виявлено.
Командна роботаЗручна спільна робота через віддалені репозиторії, pull request та code review.
Індекс (staging area)Можна точно вибрати, які зміни потраплять у коміт.
Безкоштовний та відкритийРозповсюджується за ліцензією GPL v2, працює на Windows, Linux, macOS.
ЕкосистемаІнтеграція з GitHub, GitLab, Bitbucket, IDE та системами CI/CD.

3. 10 базових команд Git з коментарями

1git config — налаштування
# Вказати ім'я та email автора комітів (виконується один раз)
git config --global user.name "Ivan Petrenko"
git config --global user.email "ivan@example.com"

Задає дані, які будуть підписувати кожен коміт.

2git init — створення репозиторію
# Ініціалізувати новий репозиторій у поточній папці
git init

Створює приховану папку .git, у якій зберігається вся історія проєкту.

3git clone — копіювання репозиторію
# Завантажити існуючий репозиторій з GitHub
git clone https://github.com/user/repo.git

Створює локальну копію віддаленого репозиторію разом з усією історією.

4git status — стан файлів
# Показати змінені, нові та проіндексовані файли
git status

Найчастіше вживана команда — показує, що змінилося з моменту останнього коміту.

5git add — додавання до індексу
# Додати один файл до індексу (staging area)
git add index.html
# Додати всі змінені файли
git add .

Готує зміни до фіксації у наступному коміті.

6git commit — фіксація змін
# Зберегти проіндексовані зміни з повідомленням
git commit -m "Додано головну сторінку"

Створює новий знімок проєкту в історії з описом зроблених змін.

7git log — історія комітів
# Переглянути історію комітів у короткому вигляді
git log --oneline

Показує список комітів: хеш, автора, дату та повідомлення.

8git branch / git checkout — робота з гілками
# Створити нову гілку
git branch feature
# Перейти на неї (або одразу: git checkout -b feature)
git checkout feature

Гілки дозволяють розробляти нові функції, не зачіпаючи основний код.

9git merge — злиття гілок
# Перейти в основну гілку і злити в неї зміни з feature
git checkout main
git merge feature

Об'єднує історію двох гілок в одну.

10git push / git pull — синхронізація з сервером
# Відправити локальні коміти на GitHub
git push origin main
# Отримати та злити зміни з віддаленого репозиторію
git pull origin main

Обмін змінами між локальним та віддаленим репозиторієм.
