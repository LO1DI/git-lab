## 1. Системи контролю версій та Git

**Система контролю версій (СКВ, VCS)** — програмне забезпечення, яке зберігає історію змін файлів проєкту, дозволяє повернутися до будь-якої попередньої версії та організувати спільну роботу кількох розробників.

| Тип | Принцип роботи | Приклади |
|-----|----------------|----------|
| Локальні | Історія зберігається лише на комп'ютері користувача | RCS |
| Централізовані | Один сервер з історією, клієнти мають робочі копії | SVN, CVS, Perforce |
| Розподілені | Кожен учасник має повну копію репозиторію | **Git**, Mercurial |

**Git** — розподілена система контролю версій з відкритим кодом, створена **Лінусом Торвальдсом** у **2005 році** для розробки ядра Linux. Git зберігає *знімки* (snapshots) стану проєкту, а кожен коміт має унікальний хеш SHA-1.

**Три стани файлів у Git:**
- **Modified** — файл змінено, але не підготовлено до коміту;
- **Staged** — зміни додано до індексу (`git add`);
- **Committed** — зміни збережено в репозиторії (`git commit`).

## 2. Основні можливості та переваги Git

- ✅ **Розподіленість** — повна копія репозиторію в кожного, робота без інтернету;
- ⚡ **Швидкість** — більшість операцій виконується локально;
- 🌿 **Гілки** — легке створення та злиття гілок;
- 📜 **Повна історія змін** — хто, коли і що змінив;
- 🔒 **Цілісність даних** — контрольні суми SHA-1;
- 👥 **Командна робота** — pull request, code review;
- 📋 **Індекс (staging area)** — точний вибір змін для коміту;
- 🆓 **Безкоштовний і відкритий** (GPL v2), кросплатформний;
- 🔗 **Екосистема** — GitHub, GitLab, Bitbucket, IDE, CI/CD.

## 3. 10 базових команд Git

```bash
# 1. Налаштувати ім'я та email автора комітів
git config --global user.name "Ivan Petrenko"
git config --global user.email "ivan@example.com"

# 2. Створити новий репозиторій у поточній папці
git init

# 3. Скопіювати існуючий репозиторій з GitHub
git clone https://github.com/user/repo.git

# 4. Переглянути стан файлів (змінені, нові, проіндексовані)
git status

# 5. Додати файли до індексу
git add index.html     # один файл
git add .              # усі зміни

# 6. Зафіксувати зміни з повідомленням
git commit -m "Додано головну сторінку"

# 7. Переглянути історію комітів
git log --oneline

# 8. Створити гілку та перейти на неї
git branch feature
git checkout feature   # або одразу: git checkout -b feature

# 9. Злити гілку feature в main
git checkout main
git merge feature

# 10. Синхронізація з віддаленим репозиторієм
git push origin main   # відправити коміти
git pull origin main   # отримати зміни
```
